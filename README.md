## App Overview

**AI Resume Analyzer** is a two-role Flutter application:

| Role | What they do |
|------|--------------|
| **Candidate (User)** | Uploads their resume (PDF/image), selects a job vacancy, and receives an AI-generated score report |
| **Recruiter (Admin)** | Creates job vacancies, receives all applications, reviews AI scores, and makes hiring decisions (Pass / Fail / High Potential) |

The AI analysis uses **Groq API** (with Llama 3.3 70B model) to score resumes. Firebase is used only for Authentication and Firestore (no Firebase Storage — files are processed locally to avoid paid tiers).

---

## Features

### Candidate Side
- Register / Login with email & password
- View all available active job vacancies
- Upload resume in **PDF, JPG, PNG** format
- Three analysis modes:
  - **Job Role Match** — AI compares resume against a specific job's required skills
  - **ATS Check Only** — Pure ATS (Applicant Tracking System) friendliness score
  - **Custom Tech Stack** — Candidate defines their own role + skills for analysis
- Detailed results: Match Score, ATS Score, Project Score, Overall Score
- See strengths, weaknesses, missing skills, and per-project breakdown
- View past analysis history
- Profile page

### Recruiter Side
- Register as Recruiter role
- Create job vacancies with: title, description, required skills, preferred skills, min experience, project type requirements
- My Vacancies tab — see only their own posted jobs
- Applicants tab — see only candidates who applied to their jobs
- Analytics tab — charts and stats scoped to their own vacancies only
- Review candidate resume details + AI scores
- Make decisions: **Pass**, **Fail**, or **High Potential**
- Add private notes to each candidate
- Settings: profile info, refresh data, sign out

## Architecture & Flow

### Candidate Flow
```
Register/Login
     ↓
Home Screen (see past analyses)
     ↓
Upload Resume Screen
     ↓
Pick File (PDF/JPG/PNG) → OCR text extraction (local, on-device)
     ↓
Select Job Vacancy  OR  Choose Custom Tech Stack  OR  ATS Only
     ↓
AI Analysis via Groq API (Llama 3.3 70B)
     ↓
Save result to Firestore (analysis collection)
     ↓
Analysis Result Screen (scores, strengths, missing skills, projects)
```

### Recruiter Flow
```
Register/Login (select Recruiter role)
     ↓
Admin Main Screen (4-tab bottom nav)
     ├── My Vacancies tab
     │       ↓
     │   View/Create job vacancies
     │       ↓
     │   Tap a vacancy → See all applicants for that job
     │       ↓
     │   Tap a candidate → Full detail + make decision
     │
     ├── Applicants tab  (all applicants across all their jobs, filterable)
     ├── Analytics tab   (charts: decisions, scores, job stats)
     └── Settings tab    (profile, refresh, sign out)
```

### State Management (Riverpod)
```
Firebase Auth Stream
      ↓
authStateProvider (StreamProvider)
      ↓
currentUserProvider (FutureProvider)
      ↓
GoRouter redirect (auto-routes based on login + role)
```

## All Screens Explained

### `LoginScreen` — `/login`
- Email + password form
- Validates input, calls `AuthNotifier.login()`
- On success: routes to `/home` (user) or `/admin` (recruiter)

### `RegisterScreen` — `/register`
- Name, email, password, role selector (User / Recruiter)
- Calls `AuthNotifier.register()` which creates Firebase Auth user + Firestore user document

### `HomeScreen` — `/home`  _(Candidate)_
- Greeting with user name
- FAB → goes to `/upload-resume`
- Lists all past analyses from `userAnalysesProvider`
- Back button shows "Exit App?" dialog

### `UploadResumeScreen` — `/upload-resume`  _(Candidate)_
- Pick file (PDF, JPG, PNG)
- Extracts text locally using `OcrService`
- Three analysis modes:
  1. **Job Role Match** — select a job from Firestore → full AI analysis
  2. **ATS Check** → ATS-only analysis
  3. **Custom Tech Stack** → enter job title + skills manually
- AI validates document type first (rejects ID cards, certificates, etc.)
- On success → navigates to `/analysis/:id`

### `AtsCheckerScreen` — `/ats-checker`  _(Candidate)_
- Simplified version: pick file → run ATS-only analysis
- Shows extracted text preview
- Result navigates to `/analysis/:id`

### `AnalysisResultScreen` — `/analysis/:analysisId`  _(Candidate)_
- Loads `AnalysisModel` from Firestore
- Shows: Overall score ring, ATS/Match/Project score bars
- Tabs / sections: Strengths, Weaknesses, Missing Skills, Projects (with per-project scores), Suggestions

### `ProfileScreen` — `/profile`  _(Candidate)_
- Shows user info
- Past analyses count

### `JobSelectionScreen` — `/job-selection`  _(Candidate)_
- Grid of active job cards from Firestore
- Candidate selects one before uploading

### `AdminMainScreen` — `/admin`  _(Recruiter)_
- Bottom navigation shell with 4 tabs
- Back button shows "Exit App?" dialog
- Badge on Applicants tab showing pending review count
- Tabs: My Vacancies | Applicants | Analytics | Settings

### `AdminVacanciesScreen` _(Recruiter — Vacancies tab)_
- Lists only the recruiter's own job vacancies (`createdBy == uid`)
- Summary header: total vacancies, active count, total applicants, pending reviews
- Each card shows skills preview, applicant count, shortlisted count
- Tap → `VacancyApplicantsScreen` for that job
- FAB to create new vacancy

### `VacancyApplicantsScreen` — `/admin/vacancy/:jobId`  _(Recruiter)_
- Shows all applicants for ONE specific vacancy
- Stats row: Avg Score, Pending, Shortlisted, Rejected
- Each card: score circle, ATS/Match/Project scores, date, decision chip
- Tap → `CandidateDetailScreen`

### `AdminCandidatesScreen` _(Recruiter — Applicants tab)_
- Shows all applicants across ALL of the recruiter's vacancies
- Filters: Job Role, Status (Pending/Pass/Fail/High Potential), Sort (Date/Score/ATS)
- Search by job title
- Tap → `CandidateDetailScreen`

### `CandidateDetailScreen` — `/admin/candidates/:candidateId`  _(Recruiter)_
- Full analysis breakdown same as candidate view
- **Decision panel**: radio buttons for Pass / Fail / High Potential
- Notes text field for private recruiter comments
- Save button calls `AdminDecisionNotifier.makeDecision()`

### `AdminAnalyticsScreen` _(Recruiter — Analytics tab)_
- Data scoped to recruiter's own vacancies only
- Overview cards: Total Analyzed, Avg Score, Pass Rate
- Decision breakdown bar chart
- Score distribution (Excellent/Good/Average/Low)
- Analysis type breakdown (Job Match / ATS / Custom)
- Per-vacancy stats
- Top missing skills across all analyses

### `AdminSettingsScreen` _(Recruiter — Settings tab)_
- Recruiter profile card (name, email, "Recruiter" badge)
- My Data: application counts, pending reviews
- My Vacancies: active count, link to create new
- Refresh Data button
- Sign Out button

### `JobCreationScreen` — `/admin/job-creation`  _(Recruiter)_
- Form: Job Title, Description, Min Experience
- Add chips: Required Skills, Preferred Skills, Project Types
- Saves to Firestore `jobs` collection with `createdBy = currentUser.uid`

## Services

### `FirebaseService` (`lib/core/services/firebase_service.dart`)
Handles all Firestore operations. **No Firebase Storage is used** — files stay on device, only extracted text is saved.

Key methods:
- `createUser(UserModel)` — save new user to `users` collection
- `getUser(uid)` — fetch UserModel
- `createJob(JobModel)` → returns document ID
- `getActiveJobs()` — jobs where `isActive == true`
- `watchJobs()` — Stream for real-time updates
- `saveResumeMetadata(...)` — save text + file name to `resumes` collection
- `saveAnalysis(AnalysisModel)` → returns document ID
- `getUserAnalyses(uid)` — candidate's own history
- `watchAllAnalyses()` — Stream for recruiter use
- `updateAdminDecision(...)` — saves recruiter decision + notes

### `AiService` (`lib/core/services/ai_service.dart`)
Makes HTTP calls to **Groq API**.

Key methods:
- `analyzeResume(resumeText, job, ...)` — Full job match analysis
- `analyzeWithCustomTech(resumeText, jobTitle, skills, ...)` — Custom stack analysis
- `analyzeAtsOnly(resumeText, ...)` — ATS-only check

Models used:
- **Analysis**: `llama-3.3-70b-versatile` (primary, high accuracy)
- **Document Classification**: `llama-3.1-8b-instant` (fast, used to detect if uploaded file is actually a resume)

The AI first checks if the uploaded file is a resume (not an ID card, certificate, payslip, etc.) before running analysis.

### `OcrService` (`lib/core/services/ocr_service.dart`)
Handles local text extraction. No internet needed.

- **PDF**: Uses `syncfusion_flutter_pdf` — extracts text directly from PDF structure (~95% confidence)
- **Images** (JPG/PNG): Uses `google_mlkit_text_recognition` — on-device ML OCR
- Auto-detects file type from extension
- Cleans extracted text (removes garbled characters, normalizes whitespace)

## Firebase Setup (Step by Step)

### Step 1 — Create Firebase Project

1. Go to [https://console.firebase.google.com](https://console.firebase.google.com)
2. Click **"Add project"**
3. Enter project name (e.g. `ai-resume-analyzer`)
4. Disable Google Analytics (optional)
5. Click **"Create project"**

---

### Step 2 — Enable Firebase Authentication

1. In Firebase Console → left sidebar → **Build** → **Authentication**
2. Click **"Get started"**
3. Click **"Email/Password"**
4. Toggle **Enable** → Save

---

### Step 3 — Create Firestore Database

1. In Firebase Console → **Build** → **Firestore Database**
2. Click **"Create database"**
3. Choose **"Start in test mode"** (for development) → Next
4. Select your region (choose closest to your users) → Enable

> ⚠️ **Test mode** allows all reads/writes for 30 days. Set proper security rules before production.

#### Firestore Security Rules (for development)
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
```

#### Firestore Security Rules (for production)
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    match /users/{userId} {
      allow read, write: if request.auth.uid == userId;
      allow read: if request.auth != null 
                  && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
    }
    
    match /jobs/{jobId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null 
                   && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
    }
    
    match /resumes/{resumeId} {
      allow read, write: if request.auth.uid == resource.data.userId;
      allow read: if request.auth != null 
                  && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
    }
    
    match /analysis/{analysisId} {
      allow create: if request.auth != null;
      allow read: if request.auth.uid == resource.data.userId 
                  || get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
      allow update: if get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'admin';
    }
  }
}
```

## API Keys — Where to Get & Where to Put

### 1. Groq API Key (for AI analysis)

**What it is**: Groq provides free, fast inference for Llama 3.3 and Llama 3.1 models. This is the brain of the resume analysis.

**How to get it**:
1. Go to [https://console.groq.com](https://console.groq.com)
2. Sign up / Log in (free account)
3. Click **"API Keys"** in the left sidebar
4. Click **"Create API Key"**
5. Give it a name (e.g. `resume-analyzer`)
6. Copy the key — it looks like: `gsk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`

**Free tier**: Groq offers generous free usage. Llama 3.3 70B is free with rate limits.

**Where to put it**:  
In the `.env` file at the **root of your project** (same level as `pubspec.yaml`):

```
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

**Which file reads it**:  
`lib/core/services/ai_service.dart` — line:
```dart
static String get _apiKey => dotenv.env['GROQ_API_KEY'] ?? '';
```

---

### 2. Firebase Config (inside firebase_options.dart)

**This is NOT a single key** — it's a config object containing multiple values automatically generated when you run `flutterfire configure`.

`lib/firebase_options.dart` contains:
```dart
static const FirebaseOptions android = FirebaseOptions(
  apiKey: 'AIzaSy...',          // Your Firebase Web API Key
  appId: '1:123456:android:...', // Your Android App ID
  messagingSenderId: '123456',
  projectId: 'your-project-id',
  storageBucket: 'your-project.appspot.com',
);
```

**How to get it**: Run `flutterfire configure` (see Step 7 above) — it generates this file automatically.

**NEVER hardcode these manually** — always use the CLI.

## Score System Explained

The AI returns 4 scores on a 0–100 scale:

| Score | What it measures | Weight |
|---|---|---|
| **ATS Score** | Resume formatting, keyword density, section structure, ATS-friendly layout | Part of overall |
| **Match Score** | How well skills/experience match the specific job requirements | Part of overall |
| **Project Score** | Quality, complexity, relevance of projects listed | Part of overall |
| **Overall Score** | Weighted composite of all three | Displayed prominently |

### Score Thresholds (defined in `app_constants.dart`)
```dart
static const int excellentScore = 80;  // Green  — "Excellent"
static const int goodScore = 60;        // Blue   — "Good"
static const int averageScore = 40;     // Orange — "Fair"
// Below 40                              // Red    — "Needs Work"
```

## Common Errors & Fixes

### ❌ `GROQ_API_KEY not configured`
**Cause**: `.env` file missing or not loaded  
**Fix**:
1. Create `.env` in project root with `GROQ_API_KEY=gsk_...`
2. Confirm `pubspec.yaml` has `.env` in `flutter: assets:`
3. Confirm `main.dart` has `await dotenv.load(fileName: ".env");`

---

### ❌ `[firebase_core] Failed to initialize`
**Cause**: `google-services.json` missing or wrong package name  
**Fix**:
1. Download `google-services.json` from Firebase Console
2. Place it in `android/app/` directory
3. Ensure `applicationId` in `android/app/build.gradle` matches the package name registered in Firebase

---

### ❌ `FirebaseException: FAILED_PRECONDITION: The query requires an index`
**Cause**: Composite Firestore index missing  
**Fix**: Click the link in the error message — Firebase will auto-create the index. Or manually create it in Firebase Console → Firestore → Indexes.

---

### ❌ Black screen or crash when navigating back
**Cause**: Mixing `Navigator.push(MaterialPageRoute(...))` with GoRouter  
**Fix**: Always use `context.push()`, `context.go()`, and `context.pop()` for navigation. Never use `Navigator.of(context).push()` in a GoRouter app.

---

### ❌ `PlatformException: Unable to load assets` (ML Kit)
**Cause**: ML Kit needs Android minSdk 21+  
**Fix**: In `android/app/build.gradle`:
```gradle
defaultConfig {
  minSdkVersion 21
}
```

---

### ❌ Analysis shows "This is not a resume"
**Cause**: The AI document classifier detected the file is not a resume (e.g. certificate, ID card, marksheet)  
**Fix**: This is intentional. The AI checks for 15+ document types before running analysis. Upload an actual resume/CV in PDF or image format.

---

### ❌ Recruiter sees all candidates, not just their own
**Cause**: Using `allAnalysesProvider` instead of `recruiterAnalysesProvider`  
**Fix**: Recruiter screens must use `recruiterJobsProvider`, `recruiterAnalysesProvider`, and `recruiterAnalyticsProvider` — all pre-filtered by `createdBy == currentUser.uid`.
